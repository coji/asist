# その OS で使えない機能は、画面にもモデルのツールにも出さない

main が起動したときに一度だけ、その OS とマシンで使える機能を決め、renderer とモデルのツールはその値だけを見る。決めるのは、ローカルの音声認識と Qwen3-TTS を動かす実行環境、エコーキャンセルのネイティブのマイク、CPU で動く Python の worker、カレンダー、グローバルショートカットのキーである。使えない機能は、選択肢もスイッチもカードもツールも出さない。ローカルの音声認識のように利用者が選ぶ場所のあるものは、その場所に使えない理由を出す。使えるはずの機能が失敗したときは、これまでどおりエラーとして見せる。ASIST が対象にしていない OS と CPU の組み合わせでは、使える機能を推測せずに起動を止める。出しておいて使うと失敗する形では、たとえば Windows の初回セットアップで MLX の音声認識と3つの追加の準備がどれも失敗し、利用者は失敗を何度も見てからでないと先に進めない。モデルもカレンダーのツールを呼ぶたびに失敗し、それを会話で説明することになる。

## 見送った案

- **renderer に OS の名前を渡し、画面ごとに判定する。** 判定が画面の数だけ散らばり、モデルに渡すツールの一覧と画面の出し分けがずれる。

## 分かっている制約

- 使えない機能が無い理由は、選ぶ場所のあるものにしか出ない。カレンダーや追加の準備は、その OS では画面から消えるだけである。
