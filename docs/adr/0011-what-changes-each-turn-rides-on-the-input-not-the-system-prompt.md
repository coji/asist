# ターンごとに変わる情報はシステムプロンプトに入れず、変わったときだけ入力に添える

実行中のジョブの経過分数のように、ターンごとに変わる情報はシステムプロンプトに入れない。その時点の状況はユーザーの発話かアプリからの通知に添え、同じ形で会話ログに保存する。添えるのは、履歴に残っている最後の状況と違うときだけにする。どのプロバイダもメッセージをシステムプロンプトの後ろにキャッシュするので、システムプロンプトが少しでも変わると、それより後ろの履歴全体を毎ターン読み直し、書き直すことになるからである。ジョブの状況はジョブが動いているあいだと終わってから30分のあいだ毎分変わるので、システムプロンプトに置くと、10万トークンの履歴ならその全部をその間の毎ターン送り直す。発話に添えて保存すれば、次のターンにも同じ形で送られるので、キャッシュされた部分は変わらない。変わったときだけ添えるのは、変わらないプロジェクトの一覧が毎ターン履歴に積み重ならないようにするためである。状況が空になったときは、モデルが最後に見た状況を今のものとして読み続けないように、空になったことを一度だけ伝える。

Gemini Live では、ジョブの状況を、セッションを開くたびに送る時刻の知らせに添える。再開したセッションは最初に開いたときの指示文を持ち続けるので、指示文に入れた状況は古いまま残るからである。ここでも、そのセッションが最後に読んだ状況と違うときだけ添える。この知らせは会話ログに保存しない。あとで開くセッションに渡す履歴には記憶の注記もジョブの状況も入れず、どのセッションも自分が開くときの知らせで今の時刻と状況を読むので、保存しても読む場所がないからである。

## 見送った案

- **システムプロンプトの最後に置き、その後ろにはキャッシュのブレークポイントを置かない。** ブレークポイントを置かなくても、メッセージのキャッシュはシステムプロンプトの後ろにあるので、毎ターン外れる。この置き方のためにあった「毎ターン変わる層」の仕組みは、同じ誤りが戻らないように削除した。
