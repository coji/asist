# OpenAI は、利用者が選んだ API キーか ChatGPT プランのどちらか一方で払い、もう一方に切り替えない

OpenAI の会話は、API キーのほかに、OpenAI がオープンソースのローカルアプリ向けに用意している「Sign in with ChatGPT」(ChatGPT プランの利用、プレビュー)でも払える。どちらで払うかは設定の `openaiAuth` で利用者が選び、選んだほうだけを使う。ChatGPT でのログインが切れたとき、プランの利用上限に達したとき、OpenAI がトークンを拒んだときも、黙って API キーで払わない。利用者が知らないうちに API の料金がかかるのを防ぐためで、失敗は「ChatGPT にログインし直す」「プランの上限に達した」と、直し方の分かる言葉で伝える。ログインは OpenAI の文書にある手順(`dynamic_agent_client` による登録、PKCE、127.0.0.1 への戻り、ID トークンの署名の検証)だけで行い、トークンは API キーと同じく safeStorage で暗号化して `userData/chatgpt.json` に置き、画面にも子プロセスにも渡さない。プランで払った呼び出しは、使用量の記録に `billing: 'chatgpt-plan'` として残し、API の単価で料金を出さない。

## 見送った案

- **ログインがあれば ChatGPT、なければ API キーを使う。** ログインの切れ目で、利用者が気づかないまま API キーに課金が移る。
- **Codex CLI に会話を任せる、または Codex CLI の認証ファイルを読む。** 会話の応答の形や速さを ASIST が決められず、ほかのアプリの資格情報を流用することにもなる。
- **OpenAI の公式の devkit(`openai/sign-in-with-chatgpt-devkit`)を使う。** 非商用のライセンスで、MIT の ASIST には組み込めない。手順は公開されている文書から実装した。
- **ログアウトしても登録(client id)を残し、次のログインで使い回す。** 登録はアカウントに結び付くので、別のアカウントでログインし直せなくなる。

## 実測

2026-10-02、Plus のアカウントで、ASIST と同じ形のリクエストを送って確かめた。function tool とその続き、暗号化した reasoning を tool の往復と次の発話をまたいで送り返すこと、`web_search`、ストリームでの `json_schema` は、API キーと同じ形で通る。`max_output_tokens` は 400 で拒まれ、`input` は配列でなければならず、ストリームでない呼び出しはできない。ストリームの完了イベントの `output` は空で、出力は各項目の完了イベントからしか読めない。`/v1/models` は `{ models: [{ slug }] }` の形で答え、`/v1/models/{id}` はスコープが足りず 403 になる。会話モデル gpt-5.6-terra の最初の文字までは 2〜4 秒で、つなぎの一言の先読み(4 秒の制限)はほとんど間に合わない。

## 分かっている制約

- プランの経路では出力の上限を指定できないので、`max_tokens` で止まることがない。
- つなぎの一言は、プランの経路ではほぼ鳴らない。
- 認証の方法やアカウントを切り替えた直後は、前の方法で暗号化された reasoning を送り返して断られるおそれがあるが、確かめていない。
- プレビューの仕組みなので、OpenAI の側で仕様が変わりうる。
