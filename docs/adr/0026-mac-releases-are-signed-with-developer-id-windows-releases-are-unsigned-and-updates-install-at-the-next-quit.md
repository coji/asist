# Mac のアプリは Developer ID で署名と公証をしてこの Mac から、Windows のアプリは署名せずに GitHub Actions から同じ Release に置き、どちらも更新は次に終了したときに入れる

配布する Mac のアプリは、この Mac で `npm run release` を実行してビルドし、Developer ID Application で署名して公証し、公開リポジトリの GitHub Release に置く。同梱した git のソースも、同じ Release に置く。アプリは electron-updater で Release を確かめ、新しいバージョンを裏で取得して、次に終了したときに入れ替える。すぐに入れ替えるのは、利用者が「このアプリについて」で「今すぐ再起動」を押したときだけにする。出したバージョンに問題があったときは、Release を消したり前のバージョンに戻したりせず、番号を上げて直したバージョンを出す。macOS はマイクの許可を署名に結び付けていて、Squirrel.Mac は今のバージョンと同じ署名の要件を満たすバージョンしか入れない。そのため、人に渡す最初のビルドから同じ Developer ID で署名する。あとから証明書を変えると、利用者の許可が外れ、自動更新も届かなくなる。会話や Agent のジョブの途中で勝手に再起動すると、話している最中の音声と作業が途切れる。electron-updater は今のバージョンより新しい番号のバージョンしか入れないので、前のバージョンに戻す方法は無い。

Windows のインストーラーは、GitHub Actions の windows-latest でビルドして、Mac のファイルと同じ Release に置く。`npm run release` は Mac のファイルで下書きの Release を作り、Windows のワークフローがその下書きにインストーラー、latest.yml、同梱した Git for Windows のソースを置いてから、Release を公開する。Windows のインストーラーには署名が無いので、秘密鍵を手元に置いておく理由が無い。

Windows のアプリも、署名が無いまま Mac と同じように自分で更新する。取得したバージョンは、次に終了したときにインストーラーが画面を出さずに入れる。「今すぐ再起動」では、すぐに入れてから ASIST をもう一度開く。署名が無いあいだは、更新を信じる根拠が、GitHub から HTTPS で取得することと、latest.yml に書いた sha512 と一致することしかない。latest.yml も同じ Release に置くので、GitHub のアカウントか Release に書き込める権限が奪われると、悪い更新をすべての Windows の利用者に配れる。Mac では Squirrel.Mac が同じ Developer ID の署名を求めるので、GitHub のアカウントを奪うだけでは配れない。この危うさを受け入れて、Windows の自動更新を署名より先に始める。

## 見送った案

- **Mac のアプリを CI でビルドして公証する。** 証明書の秘密鍵と、Apple ID の認証情報を GitHub の Secrets に置くことになる。配布は多くないので、この Mac のキーチェーンから出さないほうを選んだ。
- **取得したらすぐに再起動して入れる。** 話している最中や、ジョブが動いている最中に、アプリが閉じる。
- **Windows のインストーラーもこの Mac でビルドする。** エージェントのランチャーとマイクのヘルパーは MSVC でビルドし、git と uv もビルドするマシンの OS のものを用意するので、Mac では Windows のアプリを作れない。
- **署名が付くまで、Windows のアプリは自分で更新しない。** 利用者は新しいバージョンに自分で気づいて、インストーラーを入れ直すことになる。直したバージョンが届くかどうかが、利用者が Release を見に行くかどうかに任される。

## 分かっている制約

- 手元で `dist:mac` したビルドは、dmg も zip も作らないので、自動更新の設定を持たず、Release から自分を更新しない。手元で `dist:win` したインストーラーも、GitHub の公開の設定をリリースのワークフローからしか受け取らないので、同じく自分を更新しない。
- 個人で Apple Developer Program に加入しているので、アプリの署名には加入者の氏名が出る。
- 以前 Apple Development で署名して入れていたアプリを Developer ID で署名したバージョンに入れ替えると、マイクの許可を一度やり直すことになる。
- electron-updater は、アプリの中の app-update.yml に発行元の名前があるときだけ、Windows の更新の署名を確かめる。そのため、Windows のインストーラーに署名を始めても、署名の無いバージョンを使っている利用者は、次の更新を署名を確かめずに入れる。
