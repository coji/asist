# Google の OAuth クライアントは、リポジトリではなくビルドの環境から入れる

Google にログインするための OAuth クライアント ID とシークレットは、リポジトリに入れない。配布するアプリには、ビルドのときの環境変数 `ASIST_GOOGLE_CLIENT_ID` と `ASIST_GOOGLE_CLIENT_SECRET` を main プロセスに埋め込み、CI ではリポジトリの secret からアプリを作るジョブにだけ渡す。リポジトリから動かすときは、同じ名前で `.env` に書く。インストールするアプリのシークレットは、Google 自身が秘密にできないものとして扱っているが、リポジトリは公開なので、書いておくと誰でも ASIST の名前で同意の画面を出し、プロジェクトの回数の上限を使えてしまう。ビルドの環境から入れれば、クライアントを作り直したときも secret を替えるだけで済む。

Google を使うよう指定したのにクライアントがないときは、起動を止めてそう伝える。

## 分かっている制約

- 配布したアプリの中身からは、クライアント ID とシークレットを取り出せる。Google の審査は、インストールするアプリについてこれを前提にしている。
- fork からのプルリクエストの CI には secret が渡らないので、そのビルドには Google のクライアントが入らない。
