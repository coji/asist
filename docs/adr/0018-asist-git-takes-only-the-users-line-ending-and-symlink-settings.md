# ASIST の git は、利用者の git の設定のうち、改行とシンボリックリンクの扱いを決める3つだけを引き継ぐ

ASIST は同梱した git を、システムの設定も利用者の設定も読まない環境で動かしている。ただし、作業ツリーのファイルをどう書き出し、どう読み戻すかを決める core.autocrlf、core.eol、core.symlinks の3つだけは、利用者の git と同じ値で動かす。Git for Windows のインストーラーは、既定でシステムの設定に core.autocrlf=true を書く。そのため利用者が clone したリポジトリでは、ファイルが CRLF でディスクにあり、コミットには LF で入っている。この設定を読まない git は、すべてのファイルのすべての行が変わったと見る。すると取り込みの前の確認がどのリポジトリでも通らず、ジョブを一度も取り込めない。また、ジョブの worktree のコミットでは、利用者の git なら LF に直す CRLF が、そのまま利用者の履歴に入る。core.symlinks が違うと、リポジトリのシンボリックリンクが、ジョブの worktree に普通のファイルとして取り出される。3つの値は、ASIST が userData に書く設定ファイルに入れ、GIT_CONFIG_GLOBAL でそのファイルを指して、利用者のグローバルの設定と同じ段で渡す。こうすると、リポジトリ自身の .git/config に書かれた値が、利用者の git と同じように優先される。値は、起動してから最初に git を使うときに一度だけ読む。git の呼び出しのたびに利用者の git を起動すると、そのたびに git の呼び出しが1回増え、同じ実行の中で、取り込みの前の確認とジョブの取り出しが違う値で動くこともありうるためである。Windows では、ASIST が同梱したものを除いて PATH で最初に見つかる git.exe を利用者の git とし、それをリポジトリの外で動かして、システムとグローバルの段の値を読む。見つからなければ何も引き継がない。macOS では利用者の git を動かさない。/usr/bin/git は、Command Line Tools が無い Mac ではインストールのダイアログを開くためである。代わりに、同梱した git でグローバルの段(~/.gitconfig など)だけを読む。Apple の git と Homebrew の git のシステムの設定は、この3つを決めていない。

## 見送った案

- **利用者の設定を何も読まない。** Windows の既定の設定で clone したリポジトリでは、ジョブを取り込めない。
- **利用者のシステムとグローバルの設定をすべて読む。** commit.gpgsign があるとコミットのたびに署名を待ち、git-lfs のようなフィルターやフックが指すプログラムは、スタートメニューや Finder から開いたアプリの PATH では見つからない。
- **3つの値を GIT_CONFIG_COUNT や -c で渡す。** コマンドラインの段はリポジトリの設定より優先されるので、リポジトリが core.autocrlf=false と決めていても上書きしてしまい、利用者の git とは違う形でファイルを読み書きする。

## 実測

2026-09-27 に Windows 11 の検証機で、同梱した MinGit を ASIST と同じ環境変数で動かして確かめた。

- Git for Windows の既定の設定(`C:/Program Files/Git/etc/gitconfig` の core.autocrlf=true)で取り出したリポジトリを、利用者の git は変更なしと見て、ASIST の git はすべてのファイルを変更ありと見た。git diff --stat では全部の行が差分になった。
- MinGit の git init は、開発者モードでシンボリックリンクを作れるマシンでも core.symlinks=false を書き、リポジトリのリンクは worktree に普通のファイルとして取り出された。

## 分かっている制約

- 利用者が設定を変えても、ASIST を起動し直すまで反映されない。
- macOS では、利用者の git のシステムの段に自分で書いた値は引き継がない。
- Windows では、ASIST を起動したときの PATH で最初に見つかる git.exe を利用者の git とみなす。ターミナルによって違う git を使っている人では、ASIST の選ぶ git が、いつも使う git と違うことがある。
- 利用者の git が動かないときや、`--show-scope` を持たない 2.26 より前の git のときは、値を読めずに、ASIST の git の操作がすべて失敗する。
- 記憶のリポジトリにも同じ値が効く。Windows で core.autocrlf=true の利用者では、整理のジョブが変えた記憶のファイルが CRLF でディスクに出る。記憶の読み込みは CRLF の行を読める。
