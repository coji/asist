# ジョブが知らせたファイルが git の無視する場所にあるときは、worktree を聞かずに片付けず、利用者に任せる

worktree で隔離したジョブのコミットには、エージェントが書いたファイルのうち git が無視するもの(dist/ や .env など)が入らない。取り込みはコミットだけを運び、取り込んだときも、変更のないジョブを片付けるときも、worktree はフォルダごと消える。そのため、エージェントが頼まれた成果物を無視される場所にだけ書くと、利用者に何も聞かないまま成果物が消えていた。ASIST は、エージェントが書いたと知らせたファイル(成果物)のうち、worktree の中にあってコミットに入っていないものを、取り込まれないファイルとして数える。続きのジョブは前のジョブが残した worktree で動くので、前のジョブとそのまた前のジョブが知らせたファイルも数える。そうしたファイルがあるジョブは、ほかに変更がなくても worktree を残して取り込み待ちにし、取り込むか捨てるかを利用者が決める。カードの差分の上と、取り込みと破棄の確認画面と、モデルが get_agent_job で読む差分に、取り込まれずに worktree と一緒に消えるファイルとして名前を出す。ほかに変更がなく、そうしたファイルだけで残したジョブは、そのファイルを記録し、ジョブの報告でもその名前を伝えて、取り込みではなく、ファイルを移してから捨てることを勧める。利用者がファイルを開いて移せるように、カードや show_files からはジョブの worktree 全体を読めるようにする。取り込んだあとは、それらを成果物の一覧から外す。記憶の整理のジョブは利用者に worktree を見せないので、この扱いにせず、これまでどおり片付ける。

## 見送った案

- **worktree に無視された新しいファイルがあれば、知らせたかどうかに関わらず残す。** 依存を入れたりビルドしたりしたジョブ(node_modules、dist、.next、__pycache__ など)が、どれも取り込み待ちのまま残る。git はそれらを取り込めないので、利用者は捨てるしかない。
- **取り込まれないファイルを、取り込みのときに取り込み先へ写す。** 取り込みの確認画面の差分に出ないファイルを利用者の作業ツリーに書くことになり、利用者が同じ場所に持っているファイル(.env など)を上書きしうる。
- **片付ける前に知らせるだけにする。** 変更のないジョブでは、知らせた時点で worktree がもう消えていて、利用者はファイルを取り出せない。

## 分かっている制約

- エージェントが成果物として知らせなかったファイル(シェルのリダイレクトで書いたものなど)は数えないので、無視される場所にあれば、変更のないジョブの worktree と一緒に消える。
- 取り込まれないファイルしかないジョブは、取り込める変更がないので取り込みを断られる。必要なファイルを開いて別の場所へ移してから、ジョブを捨てる。
