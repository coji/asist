# エージェントが worktree を別のブランチに切り替えたジョブは ASIST では取り込まず、そのブランチの名前を伝えて利用者に任せる

ジョブの worktree は、ASIST が作ったジョブのブランチを開いた状態で始まる。ジョブが終わると、ASIST はそのブランチに残りの変更をコミットし、取り込みの差分をそのブランチから数える。エージェントは「ブランチを切ってコミットして」と頼まれると、worktree の中で自分のブランチに切り替えたり、ジョブのブランチの名前を git branch -m で変えたりしてコミットすることがある。ジョブが終わったときに worktree の HEAD がジョブのブランチを指していなければ、ASIST は何もコミットせず、worktree をそのまま残して取り込み待ちにし、エージェントが開いたブランチの名前(名前を変えたときは新しい名前)を記録する。HEAD が detached なら、そのコミットを記録する。そうしたジョブは ASIST では取り込まない。カード、ジョブの報告、get_agent_job と、取り込みを頼まれたときに断る理由で、ASIST では取り込めないことと、そのブランチの名前と、利用者が自分で取り込むか捨てられることを伝える。差分を読むたびにも worktree の HEAD を確かめ、ジョブのブランチを指していなければ同じ理由で断る。

## 見送った案

- **エージェントのブランチのコミットを、ASIST の取り込みで取り込めるようにする。** ブランチを頼んだ利用者は、取り込みではなくブランチそのものを望んでいることが多い。また、エージェントが開いたブランチが利用者自身のブランチのこともあり、ASIST がそこにコミットを足したりそこから取り込んだりすると、利用者のブランチが頼まれていない形で動く。

## 分かっている制約

- 捨てると、worktree と、そこにしかない変更(コミットしていない変更や、detached HEAD で作ったコミット)が消える。エージェントのブランチとそのコミットは、利用者のリポジトリに残る。ジョブのブランチは、名前を変えられてもう無いときはそのままで、捨てることは終わる。
- 続きのジョブは同じ worktree で動く。終わったときにまだ別のブランチが開いていれば、同じように取り込まない。
