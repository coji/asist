# Mac では、Agent が終わったことを、CLI のグループ、CLI が起動したプロセス、トークンを持つプロセスのどれも残っていないことで確かめる

claude と codex は、エージェントが動かすコマンドを、それぞれ別のセッションやプロセスグループで起動する。claude 2.1.276 の Bash ツールはシェルを `detached` で起動し、codex 0.137.0 はコマンドを自分のプロセスグループに入れる。そのため CLI のプロセスグループが空になっても、コマンドが残って worktree に書き続けることがある。そこで Mac では、グループの外にあるエージェントのプロセスを 2 つの方法で見つける。1 つは、ジョブが動いているあいだ 0.5 秒ごとにプロセスの一覧を読み、CLI の子孫を親の pid でたどって、起動時刻とともに覚えておくことである。別のセッションで動くコマンドも、CLI が動いているあいだは CLI の子なので、CLI が終わって launchd の子になる前に覚えられる。もう 1 つは、ASIST が起動のたびに環境変数 `ASIST_AGENT_EXECUTION_ID` に入れるトークンを、環境に持つプロセスを探すことである。停止では、CLI のグループと、覚えた子孫のうちまだ動いているものと、トークンを持つものに信号を送り、どれも残っていないときにジョブが終わったとみなす。CLI が自分で終わったときに残ったものも同じように止めてから、worktree をコミットするか片付ける。止めきれなかった停止は、もう一度頼むと信号を送り直す。

どちらか一方では足りない。Apple がシステム整合性保護の下で配る `/bin/zsh`、`/bin/sh`、`/bin/bash`、`sleep`、`cat` などは、`ps` に環境を見せないので、トークンでは見つからない(macOS 26.2、2026-10-02)。claude と codex はコマンドをこうしたシェルで動かすので、トークンだけでは、いちばんよくある形のコマンドを見落とす。一方、一覧を読む前に親が終わったプロセスは、親をたどっても見つからず、トークンでしか見つからない。

## 見送った案

- **CLI のプロセスグループだけを見る。** 別のグループに移ったコマンドを数えないので、止めないまま worktree をコミットしたり消したりし、アプリの終了も許してしまう。
- **トークンだけで探す。** Apple が配るシェルとコマンドの環境は読めないので、`/bin/zsh -c` で動くループのようなコマンドが残る。
- **止めるときに親子のつながりをたどる。** CLI が先に終わると、残ったコマンドは launchd の子になり、たどれなくなる。そのため、ジョブが動いているあいだに覚えておく。

## 実測

- 止めているあいだの 1 回の確かめに、約 45 ms かかった。プロセスの一覧が約 10 ms、利用者のすべてのプロセスの環境が約 25 ms、そこで見つかったプロセスを読み直すのが約 10 ms である(Apple M5、プロセス 724 個のうち利用者のもの 514 個、2026-10-02)。main のスレッドで読むので、CLI のグループの確かめ(25 ms ごと)よりも間をあけて、500 ms ごとに読む。ジョブが動いているあいだの一覧は、main のスレッドを止めずに読む。

## 分かっている制約

- 再起動のあとの回収では、子孫はすでに launchd の子になっていてたどれないので、グループの外はトークンだけで探す。Apple が配るシェルとコマンドが残っていても見つからない。グループの中にそれらが残っていると、トークンを確かめられないので、止めずに理由を出す。
- 一覧を読む 0.5 秒のあいだに親が終わったプロセスのうち、Apple が配るシェルとコマンドは、どちらの方法でも見つからない。
- 子孫は起動時刻で見分けるが、`ps` は起動時刻を地方時で出すので、ジョブのあいだに Mac のタイムゾーンが変わると、覚えた子孫を見失う。
- エージェントがジョブの中で起動して残した開発用のサーバーのように、自分では終わらないプロセスも、ジョブの終わりに止まる。
