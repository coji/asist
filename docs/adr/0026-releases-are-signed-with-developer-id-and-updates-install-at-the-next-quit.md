# 配布するバージョンは Developer ID で署名と公証をしてこの Mac から Release に置き、更新は次に終了したときに入れる

配布するアプリは、この Mac で `npm run release` を実行してビルドし、Developer ID Application で署名して公証し、公開リポジトリの GitHub Release に置く。同梱した git のソースも、同じ Release に置く。アプリは electron-updater で Release を確かめ、新しいバージョンを裏で取得して、次に終了したときに入れ替える。すぐに入れ替えるのは、利用者が「このアプリについて」で「今すぐ再起動」を押したときだけにする。出したバージョンに問題があったときは、Release を消したり前のバージョンに戻したりせず、番号を上げて直したバージョンを出す。macOS はマイクとカレンダーの許可を署名に結び付けていて、Squirrel.Mac は今のバージョンと同じ署名の要件を満たすバージョンしか入れない。そのため、人に渡す最初のビルドから同じ Developer ID で署名する。あとから証明書を変えると、利用者の許可が外れ、自動更新も届かなくなる。会話や Agent のジョブの途中で勝手に再起動すると、話している最中の音声と作業が途切れる。electron-updater は今のバージョンより新しい番号のバージョンしか入れないので、前のバージョンに戻す方法は無い。

## 見送った案

- **CI でビルドして公証する。** 証明書の秘密鍵と、Apple ID の認証情報を GitHub の Secrets に置くことになる。配布は多くないので、この Mac のキーチェーンから出さないほうを選んだ。
- **取得したらすぐに再起動して入れる。** 話している最中や、ジョブが動いている最中に、アプリが閉じる。

## 分かっている制約

- 手元で `dist:mac` したビルドは、dmg も zip も作らないので、自動更新の設定を持たず、Release から自分を更新しない。
- 個人で Apple Developer Program に加入しているので、アプリの署名には加入者の氏名が出る。
- 以前 Apple Development で署名して入れていたアプリを Developer ID で署名したバージョンに入れ替えると、マイクとカレンダーの許可を一度やり直すことになる。
