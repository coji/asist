# ファイルのカードで開くドキュメントは、そのフォルダの中だけを読み込み、外のサーバーにはつなげない

ファイルのカードで開いた HTML のページと、ブラウザがスクリプトを動かすその他のドキュメント(SVG など)は、`asist-file` で配るときに、そのファイルが入っているフォルダとその下だけを読み込める CSP(`documentPolicy`)を付けて配る。読み込めるのは自分のフォルダのスクリプト・スタイル・画像・フォント・メディアと、ドキュメント自身が持つ `data:` と `blob:` だけで、ほかのフォルダのファイルも、外のサーバーの資源も読み込めない。`connect-src 'none'` で `fetch`・`sendBeacon`・WebSocket をふさぎ、フォームの送信、フレーム、ワーカーからの外への通信もふさぐ。さらに、こうしたドキュメントは一つのファイルを見せるだけのもので自分のフレームを動かすことはないので、`asist-file` のドキュメントを表示しているフレームからの別アドレスへの移動は main が拒む(`will-frame-navigate`)。最初に about:blank からそのファイルへ移る読み込みと、地図カードの Google のフレームはそのまま通す。

`sandbox allow-scripts` でページのオリジンは不定になり、アプリの画面や preload のブリッジには触れられない。この `asist-file` という scheme は特権付きで CORS を有効にしているため、この CSP が無ければ、オリジンが不定のページでも許可したフォルダのほかのファイルの中身を読み、それをどの https のサーバーへも送れてしまう。CSP の source はホストを必要とするが、ローカルのパスの `asist-file` URL にはホストが無いので、空のホストの代わりに `*` を置き、パスでフォルダに閉じ込める。Windows の共有のときはサーバー名をそのままホストにする。

## 見送った案

- **これまでどおり、CDN からスクリプトやスタイルを読み込めるようにする(`script-src`/`img-src` などに `https:`、`connect-src https:`)。** レポートがグラフの部品を CDN から読むためという当初の許可だったが、外の https へ出す口はそのまま、読み取った中身を外へ送る口になる。「外へつなげない」ことと「任意の https を読み込める」ことは両立しないので、外部の読み込みはやめ、ドキュメントは自分のフォルダの中で完結させる。
- **サブリソースの要求ごとに、main 側でもページのフォルダの外を拒む。** `asist-file` の要求にはどのページが出したのかが載らない(Referer を付けず、オリジンも不定)ので、要求ごとにページのフォルダを知る術がなく、これを入れるにはこの scheme の作り直しが要る。閉じ込めで読めるものを外へ送る口はすべて閉じてあるため、下の制約の範囲で別の許可フォルダの中身がページに読めても、それを持ち出すことはできない。そこで main 側の追加の確認は入れず、読める範囲を下に明記するだけにした。

## 分かっている制約

- ページは外部の資源を読み込めないので、CDN のライブラリに頼るレポートは、部品を自分のフォルダに同梱するか、ページの中に埋め込む必要がある。
- 閉じ込めは CSP のパスで行う。同じフォルダの中にあるファイルどうしは、これまでどおり互いの中身を読める。ページのフォルダの中にある、別の許可フォルダを指すシンボリックリンク(クローンしたリポジトリや展開した zip の中など)をたどった先や、ページを広いフォルダ(たとえば Downloads)の直下に置いたときのそのフォルダ全体は、URL がそのページのフォルダの下に収まる限り読める。どちらも読めるだけで、外へは送れない。
- 外へ向かう合図として一つだけ残るのは、ドキュメントが自分で足した `<link rel="dns-prefetch">` によるホスト名の名前解決(ドキュメントが選んだ名前の DNS 参照)である。Electron にはこれをフレーム単位で止める術がない。出ていくのはホスト名だけで、応答は返らず、ファイルの中身を送る帯域にはならない。`rel="preconnect"` は、Electron が renderer の要求だけでは接続しないので何もしない。ドキュメントが持つリンクの暗黙の先読みは、応答ヘッダー(`X-DNS-Prefetch-Control: off`)で止めてある。
