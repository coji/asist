# Mac では、ASIST が終わると、動いている Agent に SIGTERM を送る

Mac の Agent の CLI は、ASIST が起動したプロセスグループで動く。ASIST は CLI を起動するたびに、別のセッションで見張りのシェルを 1 つ起動する。見張りは、ASIST だけが書き込むパイプを読んで待つ。CLI が終わると ASIST はそのパイプに 1 行書き、見張りは何もせずに終わる。1 行が来ないままパイプが閉じたとき、つまり ASIST が落ちたり強制終了されたりしたときは、見張りは CLI のプロセスグループと、その時点で CLI からたどれる子孫のプロセスに SIGTERM を送る。見張りが無いと、CLI は出力を読む相手がいなくなっても作業を続け、そのあいだは画面から止められず、ログも残らない。Windows では launcher が ASIST の終了で Job を止める。

見張りを起動できないとき、たとえばプロセスの数が上限に達しているときは、CLI を始めずにジョブを失敗にする。見張りは ASIST が落ちても止められない Agent を動かさないためにあり、ジョブのエラーにその理由が出るので、利用者はあとで始め直せる。

## 見送った案

- **次の起動の回収に任せる。** 作業が終わるまで、または利用者が ASIST を起動し直すまで、誰も見ていない Agent が書き続け、そのあいだのログは残らない。
- **見張りを CLI のプロセスグループの中に置き、`kill -TERM 0` でグループに送る。** CLI が自分で終わったあとも見張りがグループに残るので、ASIST はそのたびに停止を始め、CLI がグループに残したプロセスの仕事も途中で止めてしまう。CLI が終わったことを 1 行で伝えても、見張りがいなくなる前に ASIST がグループを確かめることが多かった。また、環境の `SHELLOPTS` に `monitor` があると、`/bin/sh`(bash)が見張りを別のグループに入れ、信号は見張りにしか届かない。
- **CLI のプロセスグループにだけ送る。** codex は自分のコマンドを別のプロセスグループで動かし、自分が SIGTERM で終わっても、動いているコマンドはそのまま最後まで動く。
- **見張りが ASIST の PID を一定の間隔で確かめる。** ASIST が終わったことに次に確かめるときまで気づかず、そのあいだ Agent は作業を続ける。パイプなら、ASIST が終わったときにすぐ分かる。
- **Windows と同じように、Mac にも起動用のプログラムを作る。** Mac には Job Object が無いので、シェルの見張りと同じことしかできず、署名する実行ファイルが 1 つ増える。
- **見張りが SIGTERM のあと、時間をおいて SIGKILL も送る。** claude も codex も SIGTERM を受けて 1 秒あまりのうちに終わったので、見張りに待つ仕組みを足すことはしない。
- **見張りを起動できなくても CLI を始め、ジョブのログとカードでそう伝える。** ASIST が落ちたら止められない Agent を動かすことになり、そのための表示もカードに要る。始め直せば済むので、そうはしない。

## 実測

いずれも 2026-10-02、Apple M5 の macOS 26.2 で確かめた。

- ASIST の代わりに CLI を起動したプロセスを強制終了すると、claude 2.1.276 は、見張りが無いときは、実行中のコマンドを終え、モデルにもう一度問い合わせ、次のコマンドも実行してから、強制終了の約 28 秒後に終わった。見張りがあると、強制終了の約 1.1 秒後に確かめたときには終わっており、実行中のコマンドも最後まで動かなかった。
- 同じように強制終了すると、codex 0.155.0 は、CLI のプロセスグループにだけ SIGTERM を送ったときは、0.1 秒のうちに終わったが、別のグループで動いていたコマンドは強制終了の 19 秒後に最後まで動いた。子孫にも送ると、そのコマンドも最後まで動かなかった。
- `/bin/echo` を CLI にして自分で終わらせると、見張りを CLI のプロセスグループの中に置いたときは、20 回すべてで ASIST が停止を始め、終わったと決まるまでの時間の中央値が 252 ms から 491 ms に延びた。終わったことを 1 行で伝えても、パイプを閉じるとすぐに確かめると 40 回中 39 回、見張りがパイプを閉じるのを待っても 40 回中 3 回、ASIST が確かめたときに見張りがまだグループに残っていた。

## 分かっている制約

- 見張りが送るのは SIGTERM だけである。SIGTERM で終わらない CLI や子孫のプロセスは、次に ASIST を起動したときの回収まで動き続ける。
- 見張りが SIGTERM を送るのは、CLI のグループと、その時点で CLI からたどれる子孫だけである。親が先に終わって CLI からたどれなくなったプロセスには届かない。次の起動の回収はそうしたプロセスをトークンで探すが、Apple が配るシェルとコマンドは `ps` に環境を見せないので、トークンでは見つからない。
- CLI が終わったあと、ASIST がグループに残ったプロセスを止めているあいだに ASIST が落ちると、見張りはもう終わっているので、残ったプロセスは次の起動の回収に任せる。
