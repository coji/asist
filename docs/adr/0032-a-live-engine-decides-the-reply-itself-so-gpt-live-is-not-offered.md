# live のエンジンには返事の中身も自分で決めるモデルだけを入れ、GPT-Live は入れない

声のエンジンの live には、聞き取りと読み上げに加えて、返事の中身の判断とツールの呼び出しも一つのモデルが行うもの(今は Gemini Live)だけを入れる。GPT-Live のように、声のモデルが聞いて話し、返事の中身は会話のモデルに任せる分け方のエンジンは入れない。GPT-Live では、声のモデルが会話のモデルに任せる合図に発話の文が付かないので、どの発話についての依頼かを、転写が届いた時刻から推し量るしかなかった。推し量りが外れると、発話が画面に出なかったり、会話のモデルに渡らなかったりした。声のモデルは会話のモデルの文を自分の言葉に言い換えて読むので、聞こえる言葉と画面の文が食い違い、どこまで読んだかも知らせないので、会話ログを転写から書けなかった。指示と料金も、声のモデルと会話のモデルの二重になった。どれも API が伝えない情報から来ているので、ASIST の側では直せない。

## 見送った案

- **GPT-Live に会話のモデルの文を書かれたとおりに読ませる。** 声と画面の食い違いは小さくなるが、どの発話についての依頼か分からないことと二重の料金は残り、GPT-Live を使う理由だった自然な話し方も弱まる。

## 分かっている制約

- 好きな会話のモデル(Claude など)を使いながら、途中で割り込める全二重の声で話す組み合わせはない。好きな会話のモデルで話すときは cascade を使い、相槌と割り込みは ASIST が判断する。
