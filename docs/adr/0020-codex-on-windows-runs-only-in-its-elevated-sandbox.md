# Windows の codex は、いつも elevated の sandbox で動かし、その準備が済んでいなければ動かさない

Windows では、codex のすべてのジョブ(読むだけのジョブ、書き込むジョブ、記憶の整理のジョブと、それぞれの続き)に `-c windows.sandbox="elevated"` を付ける。Windows の codex は、`windows.sandbox` で sandbox を指定しないと、何も閉じ込めずに動く。ASIST は、利用者のモデルの好みでジョブの動きが変わらないように `--ignore-user-config` で codex を動かしているので、利用者が自分の設定で sandbox を選んでいても、その設定はジョブに届かない。指定しないままでは、書き込むジョブがフォルダの外に書き、ネットワークにもつながる。macOS で codex の sandbox が守っている境界、つまり書き込むジョブがフォルダの外に出るには自動のレビューを通ることと、記憶の整理のジョブが worktree の外に書けずネットワークにもつながらないことが、Windows では無くなってしまう。elevated の sandbox を使うには、ローカルのユーザーを作る一度きりの準備が要り、その準備には管理者の権限が要る。準備が済んでいないマシンでは、codex が見つからないときと同じように扱い、ジョブを始めずに、ターミナルで codex を一度起動して Windows の sandbox を準備するように案内する。タイマーで始まる記憶の整理のジョブが、誰も見ていないときに管理者の権限を求めることがあってはならないためである。準備が済んだかどうかは、codex が準備のあとに残すファイル(codex のホームの `.sandbox\setup_marker.json`)があるかどうかで判断する。claude は Windows でも macOS と同じ引数で閉じ込められたので、変えない。

## 見送った案

- **unelevated の sandbox を使う。** 管理者の権限の要る準備は要らないが、検証機ではすべてのコマンドが起動に失敗した。
- **準備が済んでいるかを確かめずに codex に任せる。** 準備の済んでいない `codex exec` がどう動くかは確かめていない。ジョブの途中で管理者の権限を求めることがありうる。
- **`--ignore-user-config` をやめて、利用者の `[windows] sandbox` の設定を使う。** 利用者のモデルの好みもジョブに効いてしまう。また、その設定を書いていない利用者のジョブは、閉じ込められないまま動く。

## 実測

2026-09-27 に Windows 11 の検証機で、codex-cli 0.157.1 を ASIST と同じ引数で、%APPDATA% の下のフォルダから動かした。エージェントに、フォルダの中に書く、フォルダの外に書く、https://example.com を取得する、フォルダの外のファイルを読む、フォルダの中で node のスクリプトを動かす、の5つを頼んだ。

- 書き込むジョブ(`--approve-for-me`)を sandbox の指定なしで動かすと、5つともできた。
- 書き込むジョブに elevated の sandbox を付けると、外に書くことは拒まれ、取得は接続できずに失敗し、残りの3つはできた。
- 記憶の整理の引数を sandbox の指定なしで動かすと、中に書くことも含めて、すべてのコマンドが "blocked by policy" で拒まれた。
- 記憶の整理の引数に elevated の sandbox を付けると、外に書くことは拒まれ、取得は接続できずに失敗し、残りの3つはできた。
- unelevated の sandbox では、すべてのコマンドが `CreateProcessAsUserW failed: 5`(アクセス拒否)で起動しなかった。

## 分かっている制約

- elevated の sandbox も macOS の workspace-write と同じく、どこのファイルでも読める。記憶の整理のジョブも、フォルダの外にある API キーのファイルを読める。ネットワークは閉じている。
- 記憶の整理のジョブは、自分の worktree の中にある検証用のスクリプトを書き換えられる。codex ではそのスクリプトも同じ sandbox の中で動くので、書き換えてもできることは増えない。
- 準備が済んだかどうかは codex のファイルで判断するので、codex がそのファイルの場所や名前を変えると、準備が済んでいても codex のジョブを始められなくなる。
- ASIST からは準備をしない。利用者が一度ターミナルで codex を起動する必要がある。
