# Excel のシートは XML のまま持ち、表示する行だけを読み解く

Excel のビューアは、プレビューの iframe の中で、選んでいるシートの XML を展開したバイト列のまま持ち、各行がどこから始まるかの索引を一度だけ作る。カードや拡大表示が行を求めると、その行のバイトだけを文字列に直して読み解き、共有文字列と書式から表示する文字を作る。共有文字列も同じようにバイト列と索引で持ち、使う文字列だけを読み解く。拡大表示はすべての行を出すが、描くのは見えている範囲とその前後 1 画面分の行だけで、離れた行は手放す。SheetJS で読み込んだシートはセルごとにオブジェクトを作るので、同じシートでも倍ほどのメモリを使い、最初の行が出るまでの時間も長いため、シートの読み込みには使わない。数値や日付を表示の書式に合わせて文字にするところだけは、SheetJS の書式の部分(SSF)を使う。

## 見送った案

- **SheetJS で選んだシートだけを読み込み、その結果を持つ。** 行を取り出す処理は短くなるが、下の実測のとおり、メモリも最初の行が出るまでの時間も多くかかる。

## 実測

2026-10-02、Apple M5(メモリ 32 GB)、headless Chrome で開いた demo(`npm run demo:viewer-budgets` の 2 つのファイル)。iframe が持つメモリは、ファイルを開いたあとにガベージコレクションをしてから、小さなブックを開いたときとの差を測った。

- 5 万行のシート(XML 19 MB)は、この方式で 21 MB、SheetJS の dense 形式で 40 MB だった。4 万行のシートが 5 枚あるブック(共有文字列 20 万個)は、22 MB と 58 MB だった。
- カードに最初の行が出るまでは、この方式で 173〜175 ms、SheetJS で 686〜869 ms だった(負荷平均 20 前後)。
