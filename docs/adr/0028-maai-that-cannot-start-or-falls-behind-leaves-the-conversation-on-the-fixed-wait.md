# MaAI を起動できないときや処理が遅れたときは、設定した無音の長さで会話を続け、そのことを一度だけ知らせる

「声」の画面で MaAI をオンにしているのに、マイクをオンにしたときに MaAI の worker を起動できなかったら(Python 環境やモデルが無い、worker が終了した、読み込みが時間内に終わらない)、マイクは止めずに、設定した無音の長さで話し終わりを判断して会話を続ける。原因は main のログに書き、利用者には、MaAI をオンにしてから最初の一度だけ、MaAI を起動できず設定した無音の長さで判断していることを知らせる。worker が動いていても、処理が会話の音に追いつかず、話し終わりの推定が 500 ms より前の音についてのものになったら、その推定は使わず、追いつくまで同じく設定した無音の長さで判断する。そうした古い推定が 5 秒続けて届き、そのあいだに遅れがさらに 500 ms 以上広がったら、マイクをオンにしているあいだに一度だけ、MaAI の処理が遅れていて、追いつくまでは設定した無音の長さで判断していることを知らせる。推定が 1 秒以上届かなかったときと、マイクをオンにし直したときは、続いた時間を数え直す。

ASIST は失敗を隠して別の動きに切り替えないことにしているが、これはその例外である。MaAI は話し終わりの判断を速くするためのもので、無くても会話はできる。MaAI のためにマイクを止めると、会話そのものができなくなる。一方で、知らせずに切り替えると、利用者は MaAI が動いていると思ったまま、返事が遅いことの理由が分からない。起動できないことは、利用者が直すまでマイクをオンにするたびに同じように起こるので、MaAI をオンにしてから一度だけ知らせる。遅れはそのときのコンピュータの忙しさで決まるので、マイクをオンにするたびに改めて判断する。遅れが広がっていることを条件にしたのは、一度止まった worker が追いつくあいだ、遅れは縮んでいくからである。5 秒は、数秒で終わる負荷では知らせが出ず、負荷が続くときにはすぐに出る長さとして選んだ。実測の 248 個から計算すると、実時間の 3 分の 2 の速さで一様に遅れる worker は、負荷がかかってから約 1.5 秒で推定が 500 ms より古くなり、約 6.5 秒で知らせが出る。動いている worker は推定を 1 秒より短い間隔で送るので、1 秒以上途切れたのは、worker が止まったか、止められたか、起動し直しているときである。そのあとの推定の遅れは、途切れる前の遅れとは関係がない。

## 見送った案

- **マイクをオンにする操作ごと失敗させる。** MaAI を直すか、設定でオフにするまで、会話ができなくなる。
- **推定が古くなったらすぐに知らせる。** ほかの処理が重なって一度止まった worker は数秒で追いつくので、知らせが出たときにはもう MaAI の推定を使っていて、知らせの内容が当たらない。
- **古い推定が続いた時間だけで判断する。** 実測の 63.8 ms から計算すると、Core i9-9900K では、worker が 2 秒止まったあと推定が 500 ms 以内に戻るまで 5.9 秒かかる。知らせが出た直後に MaAI が追いつき、知らせの内容が当たらなくなる。
- **マイクの音が届くたびに、最後に使えた推定からの時間で遅れを判断する。** 推定を送らなくなった worker も遅れていることになり、終了して起動し直しているだけの worker についても、処理が遅れていると知らせてしまう。

## 実測

- 2026-10-02、負荷の高い Mac で、音を実時間で渡した worker は 30 秒に 248 個の推定を送った。推定どうしの間隔は最大でも 401 ms で、推定は最大で 7.5 秒前の音についてのものだった。
- 2026-10-02、Apple M5(メモリ 32GB)で、ほかの作業による負荷平均が 11〜15 のときに、アプリと同じ MaAI とモデルで worker を 15 秒動かすと、1 フレームの処理は中央値 42〜43 ms、90 パーセンタイル 51〜54 ms で、推定どうしの間隔は最大 163 ms だった。warm-up の最初の結果で ready を送っていたときは、ready 直後の推定は 800 ms 前の音についてのもので、ready から 405 ms のあいだ 500 ms を超えていた。warm-up を処理し終えてから ready を送ると、最初の推定から遅れは 0 ms だった。負荷平均が 15 前後の別の実行では、1 フレームの中央値が 196 ms になり、途中で worker を 2 秒止めたこともあって 14 秒のうちに 8.08 秒まで遅れ、MaAI がたまった音を捨てて 0.56 秒に戻り、また遅れていった。
- 2026-09-27、Windows 11 の Core i9-9900K で、1 フレームの処理は中央値 59.8 ms、90 パーセンタイル 63.8 ms、最大 66.7 ms だった。

## 分かっている制約

- 会話の途中で worker が終了し、起動し直せなかったときは、ログに書くだけで、その場では知らせない。次にマイクをオンにしたときの起動も失敗すれば、まだ知らせていない場合に限って知らせる。
- 遅れは worker が送ってくる推定だけで判断する。推定をまったく送らなくなった worker は、遅れとしては知らせない。
- 遅れたまま、それ以上広がりも縮みもしない worker については知らせない。
- 相槌と頷きのモデルだけが遅れたときは知らせない。そのあいだ、相槌は文字だけで判断する。
- MaAI がオフのとき、日本語以外で会話しているときは、起動しないので何も知らせない。
