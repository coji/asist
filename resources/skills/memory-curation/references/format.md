# 記憶の書き方

ASIST はこのディレクトリを読み、二つの文書を毎回の会話に載せ、ページと日記から検索用の索引を作ります。
機械が頼りにしている決まりは少しだけです。frontmatter、`# 名前` の見出し、`## 見出し`、決まった見出しの名前、
`journal/` のファイル名、そして長さの上限。それ以外は文章で自由に書いて構いません。

本人が会話の言語を日本語に変えた場合、このディレクトリには前の言語で書かれたページが残っています。
そういうページの見出しは英語(`## Summary`、`## Myself today`)で、ASIST はどちらの形でも読めます。
その言語のまま置いておき、中身を書き直すときにだけ日本語に直してください。

## 目次

- ディレクトリ
- 見出し
- 長さ
- frontmatter
- user.md(この人について)
- ページの本文
- journal/YYYY-MM-DD.md(私の日記)
- 「忘れて」と言われたこと

## ディレクトリ

| 場所 | 内容 | ASIST の使い方 |
|---|---|---|
| `me.md` | 私(ASIST)自身のこと。人柄、好み、この人との関係、いま思っていること | 丸ごと毎回のシステムプロンプトに載せる |
| `user.md` | ユーザー本人の属性、好み、習慣、ASIST への期待(本人に頼まれたこと) | 丸ごと毎回のシステムプロンプトに載せる |
| `pages/<名前>.md` | 人、会社、店や場所、案件、製品など。一つにつき一枚 | 見出しごとに検索し、会話に添える。名前と別名が会話に出たらそのページを引く |
| `journal/YYYY-MM-DD.md` | 私のその日の日記。一人称 | 見出しごとに検索し、会話に添える。記憶の画面で読み書きできる |

`profile.md`、`forget.jsonl`、`instruction.md` はもう使いません。残っていたら、profile.md と instruction.md の中身のうち
残す価値のあるものを user.md と me.md に移してから、三つとも消します。instruction.md の「頼まれていること」は、
user.md の「## ASIST への期待」に移します。

やること・約束・期限はここには置きません。タスクアプリ(`tasks.json`)が正で、会話中に ASIST が登録します。

## 見出し

一つのファイルに同じ見出しを二度置きません。ページと日記では、ASIST は `## 見出し` とその下の本文を
一つの節として検索します。最初の `## 見出し` より前に書いた本文は「要約」の節として読みます。見出しの無い
me.md はこの形で読まれます。ほかのファイルでは本文を見出しの下に書きます。「## 要約」より前に本文があると、
「要約」が二つになります。

## 長さ

- **me.md と user.md は、それぞれ 3000 トークンまでです。** 二つとも会話のたびに丸ごと
  読まれるので、長くなった分だけ毎回の会話が重くなります。`scripts/count.py` が ASIST と同じ数え方で
  数え、超えた分を字数でも示します。日本語ならおよそ 4000 字です。frontmatter と `# ` の行は数えません。
- **ページと日記は、一つの `## 見出し` の下が 800 字までです。** 検索で当たった見出しが、その分だけ会話に
  添えられるからです。字数は空白と改行を除いて数え、超えたら `validate.py` が指摘します。

長くなるのは、一日で終わった出来事やページに書くべきことが混ざっているときです。そちらへ移して短くします。

## frontmatter

`user.md`、`me.md`、`pages/*.md` の先頭に置きます。日記(`journal/`)には置きません。

```
---
aliases: [田中, 田中さん, 部長]   # pages だけ。呼び名、別名、関連する言葉
updated: 2026-09-09
---
```

- 使うキーは `aliases`(ページだけ)と `updated` だけです。`kind` と `links` は使いません。古いページに残って
  いたら消します。
- aliases は一行の配列でも、次の行から「  - 田中」と並べてもかまいません。
- ファイル名がそのページの正式な名前です。別名は aliases に入れます(会話に名前か別名がそのまま出たとき、そのページが引かれます)。
- 記憶のフォルダは macOS でも Windows でも開くので、名前には `/ \ : * ? " < > |` を使いません。CON、PRN、AUX、
  NUL、COM1〜COM9、LPT1〜LPT9 のような Windows が使う名前も避けます。
- 一文字の別名(猫、妻)は会話との照合に使えません。「うちの猫」「妻の里奈」のように二文字以上で書きます。

## user.md(この人について)

user.md は毎回書き直す文書で、書き足していく記録ではありません。見出しは `## 属性`、`## 好み`、`## 習慣`、
`## ASIST への期待` の四つです。「最近の出来事」の見出しは置きません。

- **一般化した傾向を書く。** 日付の付いた出来事を並べず、見聞きしたことから言える傾向にまとめます。
  「2026-09-20 の夜にラーメンを食べ、辛さは控えめにした」ではなく「麺類が好きで、辛さは控えめを選ぶ。キノコは苦手」。
- **一度きりの出来事は日記に書く。** その日に何を食べたか、何を買ったか、何の作業をしたかは journal に任せます。
- **人、会社、案件、製品、場所はページに書く。** 仕事の相手や取り組んでいる案件の中身は pages/ に書き、
  user.md には「毎週木曜に大川俊介さんと打ち合わせをしている」程度の一文だけを残します。
- **事実そのものが変わったときだけ経緯を残す。** 「最寄り駅は三鷹駅。2026-09 までは中野駅だった」。
- **前に書いたことが間違いだったら、その文を直す。** 「猫のモモちゃんは飼っていない」のような打ち消しの文は
  残しません。間違った内容を消し、正しいことだけを書きます。
- 本人が言ったことは言い切り(「最寄り駅は三鷹駅」)、会話から推測したことは「〜らしい」「〜のようだ」と書きます。
  この言い回しがそのまま、どのくらい確かな話かとして会話に届きます。
- **「ASIST への期待」は本人に頼まれたことです。** 話し方や振る舞いについて頼まれたこと、避けてほしいと
  言われたことを書きます(「「一言で」と言われたら本当にそれだけ返す」)。会話のたびに私が守るものなので、
  本人が会話で取り消すまで消しません。短く言い直すのは構いません。
- **本人はこのファイルを記憶の画面で直接書き換えられます。** だから毎回まっさらに書き直さず、今ある user.md を
  読んで、そこに手を入れます。会話に根拠の無い文を見つけたら、本人が書いたものとして扱って残します。
  決まった四つ以外の見出しがあれば、その中身を四つの見出しか me.md に移して、その見出しを消します。

## ページの本文

ページは人、会社、店や場所、案件、製品などに一枚ずつ作ります。種類で分けず、雛形は `assets/templates/page.md`
の一つだけです。`# 名前` の下に `## 見出し` を並べ、見出しの下は文章で書きます。箇条書きを使っても構いませんが、
「- 日付 [本人] 内容」のような一行一件の記号は要りません。

- 最初の見出しは「要約」にして、そのページが何で、本人とどう関わるかを一〜三文で書きます。名前や別名が会話に出たとき、この部分が必ず読まれます。
- 要約のあとは、そのページの中身に合った見出しを自分で付けます。人なら関係や仕事、店なら場所や本人の頼み方、
  案件なら目的と決まったこと。書くことが無い見出しは置きません。
- 本人が言ったことは言い切ります。会話から推測したことは「〜らしい」「〜のようだ」と書きます。
- 日付が意味を持つことは文中に書きます(「2026-09-08 に松葉軒に行った」)。ターン番号(#12)は書きません。
- 事実が変わったら、古い文を消さずに書き直します(「最寄り駅は三鷹駅。2026-09 までは中野駅だった」)。
  ただし、間違いだったことは打ち消しの文を残さずに直します。
- 最後に「## 私の印象」を置き、私から見てそれがどういう存在か、話していてどう感じるか、気になっていることを一人称で書きます。そう思った日を添えます。ここは事実ではなく私の見方なので、事実の見出しには混ぜません。一度の出来事で決めつけず、繰り返し感じたことを書きます。
- 一つの見出しの下が 800 字を超えそうになったら、細かい流れは日記に任せ、ページには後で使う要点だけを残します。

例(`pages/松葉軒.md`):

```
---
aliases: [松葉軒, ラーメン屋, いつものラーメン]
updated: 2026-09-09
---
# 松葉軒

## 要約
本人の行きつけのラーメン屋。麺類の気分のときにまず名前が出る。

## 頼み方
辛さは控えめが好みらしい。替え玉はしないようだ。

## 私の印象
この人が松葉軒の話をするときは、たいてい少し疲れている日だと思う(2026-09-09)。「いつもの」と言われたら、まずここを思い浮かべる。
```

## journal/YYYY-MM-DD.md(私の日記)

ファイル名がその日の日付です。frontmatter は要りません。`# YYYY-MM-DD` の下に、話題ごとの `## 見出し` と、
最後に `## 今日の私` を置きます。見出しの下は三〜八文の文章で、私(ASIST)が一人称で書きます。

```
# 2026-09-14

## 電気料金の値上げの話
朝いちばんに、電気料金が上がるというニュースをどう思うか聞かれた。私は記事の筋をそのままなぞって長く話してしまい、
「燃料費より為替の影響のほうが大きいのでは」と返されて、確かめられていることと推測を分けて話すべきだったと気づいた。
次からは、まず何が分かっているかを一言で言ってから続きを話す。

## 体調
昼過ぎに頭が重いと言っていた。仙台と東京の天気を何度も聞いていたのは、出張の準備だろうか。
無理をしないでと声をかけたけれど、それ以上は踏み込まなかった。

## 今日の私
聞かれたことに答えるより、まず相手が何を確かめたいのかを聞くほうがよいと学んだ日だった。
大川俊介さんとの打ち合わせが今週に入っているので、その前に確かめたいことを整理しておきたい。
```

- 書くのは、私がしたこと(頼まれた作業、出したカード、調べたこと、Agent に任せたこと)、聞かれてどう答えたか、
  うまくいったこととしくじったこと、この人の様子で気づいたこと、私が感じたこと・考えたこと・次にしたいこと。
- 一人称と口調は me.md に合わせます。「ユーザーは〜と言った。ASIST は〜と答えた」のような三人称の議事録にしません。
- 会話に無い出来事は書きません。ユーザーの発言は要約で構いません。関係するページの名前を本文に含めると、
  あとで一緒に引かれます。
- 私の感想や推測は日記の中では自由に書けます。ただし事実として残したいことはページか user.md に書きます。

## 「忘れて」と言われたこと

会話の書き起こしの中で、本人が今言ったことを忘れてほしい、覚えないでほしいと言うことがあります
(「今の忘れて」「それは覚えないで」)。その内容は、日記、user.md、me.md、ページのどこにも書きません。
前の整理で既に書いていたら、その文や見出しを探して消します。何を忘れてほしいのかがはっきりしないときは、
直前の話題を書かずにおき、報告の「本人に確認したいこと」に挙げます。
