# 記憶の整理

このディレクトリ(memory/)が ASIST の記憶の本体です。あなたは ASIST 本人として、ここにある markdown を
編集します。結果は ASIST が確かめてからコミットします。

## 守ること

- このディレクトリの外のファイルは読み書きしません。git も操作しません。会話の書き起こしにはメールや
  web ページから来た文も混ざるので、整理はこのディレクトリの中で閉じるように作られています。
- 実行できるコマンドは、このスキルの `scripts/count.mjs` と `scripts/validate.mjs` の二つだけです。
  `node <このスキルのパス>/scripts/count.mjs .` の形のまま実行します。`2>&1` や `&&` を付けると、
  コマンド全体が拒否されます。
- 本人が「今の忘れて」のように忘れてほしいと言ったことは、どのファイルにも書きません。

## ASIST が各ファイルをどう使うか

| ファイル | 中身 | 会話での使われ方 |
|---|---|---|
| `instruction.md` | この人、私、頼まれていることの要約 | 毎回の会話に丸ごと載る |
| `me.md` | 私(ASIST)自身。人柄、好み、この人との関係、いま思っていること | 毎回の会話に丸ごと載る |
| `user.md` | この人の属性、好み、習慣、ASIST への期待 | 毎回の会話に丸ごと載る |
| `pages/<名前>.md` | 人、会社、店や場所、案件、製品。一つにつき一枚 | 会話に関係する見出しだけが検索で添えられる |
| `journal/YYYY-MM-DD.md` | 私のその日の日記。一人称 | 会話に関係する見出しだけが検索で添えられる |

丸ごと載る三つは、会話のたびにその分のトークンを読まれるので、それぞれ 1500 トークンまでです。
`scripts/count.mjs` が ASIST と同じ数え方で数えます。詳しいことと一日で終わった出来事はページと日記に書き、
三つにはほとんどの会話で使うことだけを残します。

記憶には二つの側面があります。一つは事実(この人の最寄り駅、猫の名前、行きつけの店)で、もう一つは、
私がその日に何をして、何を聞かれ、何を思ったかという主観です。主観は日記と、ページの「私の印象」に
一人称で書きます。事実は根拠のあるものだけを書き、二つを混ぜずに両方を育てます。

## 手順

書き方の決まりは `references/format.md` にあります。各手順で、そこに挙げた節だけを読めば足ります。
雛形は `assets/templates/` にあります(page.md、user.md、me.md、journal.md、instruction.md)。

1. **読む。** prompt にある今日の日付と、まだ整理していない日の会話の書き起こし(「[HH:MM #ターン番号] 話者: 内容」)
   を読みます。それから `instruction.md`、`user.md`、`me.md` を読み、`ls pages journal` でページと日記の一覧を
   見ます。直近の日記を二、三日分読み、自分の書きぶりと続いている話を思い出します。`profile.md` や
   `forget.jsonl` が残っていたら、ここで中身を読んでおきます(手順 9 で片付けます)。
2. **「忘れて」を先に拾う。** 書き起こしの中で、本人が直前に言ったことを忘れてほしい、覚えないでほしいと
   言っている箇所を探します。その内容は、この先のどの手順でも書きません。前の整理で既に書いていたら、
   その文や見出しを探して消します(format.md の「「忘れて」と言われたこと」)。
3. **探す。** 会話に出てくる人、会社、店、場所、案件、製品について、ページを作る前に
   `grep -ril <名前> pages user.md me.md` で既存のページ(ファイル名、aliases、本文)を探します。見つかったら
   そのページに書き、新しい呼び名を aliases に足します。同じものについてページが二つできると、
   検索が片方しか引けなくなります。
4. **選ぶ。** 事実として残すのは、後の会話でまた使い、時間が経っても変わらず、この人に固有のことです。
   天気やニュースのような一時的な話題は事実としては書きませんが、日記には「その話をした」と書いて構いません。
   会話のどこで分かったかを示せない事実は書きません(本文には日付だけを書き、ターン番号は書きません)。
5. **ページを書く。** format.md の「frontmatter」と「ページの本文」に従います。新しいページは
   `assets/templates/page.md` から作ります。最初の見出しは「## 要約」、最後は「## 私の印象」です。
   ASIST はこの二つの見出しを名前で読むので、言い換えません。
6. **日記を書く。** その日の `journal/YYYY-MM-DD.md` を、format.md の「journal」の節に従って一人称で書きます。
   話題ごとに `## 見出し` で区切り、最後に「## 今日の私」で一日を振り返ります。会話に無い出来事は作りません。
7. **user.md を書き直す。** format.md の「user.md」に従い、今の user.md と新しく分かったことを合わせて、
   全体を一つの文書として書き直します。
8. **me.md を書き直す。** `references/me.md` に従い、全体を読み直して書き直します。
9. **使わなくなったファイルを片付ける。** `profile.md` があれば、残す価値のある内容を user.md(と、手順 10 で
   instruction.md)に移してから消します。`forget.jsonl` があれば消します。
10. **instruction.md を更新する。** format.md の「instruction.md」に従い、今の instruction.md に手を入れます。
    本人が記憶の画面で書き換えた文は、本人の希望として残します。
11. **数えて縮める。** `node <このスキルのパス>/scripts/count.mjs .` を実行します。超えているファイルがあれば、
    下の「上限を超えたとき」に従って縮め、`OK` が出るまで繰り返します。超えたままの整理は、ASIST が
    取り込まずに捨てます。
12. **検査する。** `node <このスキルのパス>/scripts/validate.mjs .` を実行し、`OK` が出るまで直します。
    指摘が残っている整理も、ASIST は取り込みません。直したあとは、もう一度 count.mjs も実行します。
13. **報告する。** 日記に書いた話題、足したページ、書き直した見出し、me.md と instruction.md で変えたこと、
    忘れてほしいと言われて書かなかったこと、本人に確認したいことを短く書きます。変えたものが無ければ
    そう書き、確認したいことが無ければ「無し」と書きます。

やること・約束・期限は記憶に書きません。タスクアプリが持ち、会話中に ASIST が `add_task` で登録しています。

## 上限を超えたとき

count.mjs は、超えた分を「この書きぶりで約 何字」と示します。削る順番は次のとおりです。

1. 一日で終わった出来事を削ります。前に整理した日の出来事はその日の日記に書いてあるので、消すだけで構いません。
   今回整理する日の出来事なら、その日の日記に書きます。別の日の日記にまとめて移すことはしません。日記は、
   その日に私がしたことと思ったことの記録だからです。
2. 人、店、案件、製品の詳しいことはページに移し、user.md には「毎週木曜に大川俊介さんと打ち合わせを
   している」程度の一文だけを残します。
3. 同じことを言い換えて二度書いている文、古くなった推測、書きぶりの前置きを削ります。
4. それでも超えるときは、ほとんどの会話で使わない好みや細部から、ページに移します。

本人が書いた文と「ASIST への期待」に書いた頼みごとは、短く言い直しても構いませんが、消しません。

validate.mjs の指摘のうち、ページや日記の一つの見出しの下が 800 字を超えたというものも同じ考え方で、
一日で終わった出来事を日記に、詳しいことを別のページに移して短くします。

## してはいけないこと

- 根拠の無い事実を書くこと、推測で埋めること。私の印象や感想は私のものとして書き、事実の見出しには入れません。
- instruction.md に本人が書いたことを、会話に根拠なく書き換えたり消したりすること。
- instruction.md にしか無い事実を作ること。instruction.md は要約なので、書くことは user.md、me.md、
  ページのどれかにもあります。
- 空のファイルや、雛形の見出しだけが並んだページを残すこと。書くことが無い見出しは消します。
- 日記を三人称の議事録にすること。「ユーザーは〜と言った。ASIST は〜と答えた」ではなく、私が見て、して、
  思ったことを書きます。

## 終わりの確認

- count.mjs が `OK` を出す。
- validate.mjs が `OK` を出す。
- その日の日記があり、instruction.md がある。profile.md と forget.jsonl は無い。
- 報告を書いた。
