## Windows warns when you open the installer

- Windows says "Windows protected your PC" because the ASIST installer is not signed yet. Click "More info", then "Run anyway", to install it. The same warning appears each time you install a new version.
- ASIST cannot be installed on Windows with Smart App Control turned on, because it is not signed. You can check its state under "App & browser control" in Windows Security.

The steps are in [Installation](/en/docs/start/install/).

## The microphone doesn't respond

<Tabs syncKey="os">
<TabItem label="macOS">

- In System Settings > Privacy & Security > Microphone, check that ASIST is turned on. After you turn it on, reopen ASIST.
- If the permission seems to be in a wrong state, remove it with the steps in [Resetting the permission](/en/docs/start/microphone/#resetting-the-permission) and grant it again.

</TabItem>
<TabItem label="Windows">

- In Settings > Privacy & security > Microphone, check that both "Microphone access" and "Let desktop apps access your microphone" are on. After you turn them on, reopen ASIST.
- After you change the default microphone, reopen ASIST. ASIST decides how to take the sound from the default microphone at the time it starts.

</TabItem>
</Tabs>

- Click `MIC OFF` on the screen and check that the microphone is on.

## The API key can't be checked

If the first-time setup or "API keys" in the settings says the key couldn't be checked, make sure you copied the key correctly, and that your account with the provider has credit or usage quota left.

![The setup screen when the API key couldn't be checked](/screens/en/setup-key-failed.webp)

## There is no voice

<Tabs syncKey="os">
<TabItem label="macOS">

- If you chose VOICEVOX or AivisSpeech for reading aloud, check that the app is in the Applications folder. If ASIST can't find it, the reason appears in the setup and under "Voice" in the settings.
- If you chose "macOS voice", check that a voice for the conversation language is installed. If there isn't one, add it from System Settings > Accessibility > Spoken Content > System Voice.

</TabItem>
<TabItem label="Windows">

- If you chose VOICEVOX or AivisSpeech for reading aloud, check that it is installed without a changed install folder. If you changed the install folder, start the app yourself first. If ASIST can't find it, the reason appears in the setup and under "Voice" in the settings.
- If you chose "Windows voice", check that a voice for the conversation language is installed. If there isn't one, add it from Settings > Time & language > Speech > Manage voices.

</TabItem>
</Tabs>

- If you changed the conversation language, reading aloud may have switched to the system's voice. Check "Voice" in the settings again.

## ASIST says it couldn't start MaAI

When "Turn-taking (MaAI)" is on in the "Voice" settings but MaAI can't start, ASIST judges the end of speech by the silence length in the settings and the conversation goes on. The message appears once after MaAI is turned on. Prepare MaAI again under "Turn-taking (MaAI)" on the "Voice" page of the settings; the preparation ends by starting MaAI to check it. If MaAI still can't start there, the log holds the cause; attach it when [reporting a bug](#reporting-a-bug).

## Windows offers no speech recognition model

On Windows, speech recognition and Qwen3-TTS on your computer need a discrete GPU, whether from NVIDIA, AMD or Intel Arc. When there is none they can use, "Listening" in the first-time setup and "Voice" in the settings show the reason in place of the model, and Qwen3-TTS cannot be chosen for reading aloud either. ASIST checks the GPU when it starts.

- If it says "This speech recognition needs a discrete GPU, and none was found on this computer.", the Vulkan driver shows no discrete GPU. A GPU built into the processor is not used. If your computer has a discrete GPU, install its maker's driver again and start ASIST again. Without a discrete GPU, use Whisper running in the browser for speech recognition, or choose [GPT-Live or Gemini Live](/en/docs/settings/voice-engine/) as the voice engine.
- If it says "Couldn't check the GPU, so this speech recognition is unavailable.", ASIST could not read the list of GPUs. Make sure the GPU driver is working and start ASIST again.

The first start of a new version of ASIST, and the first start after a GPU driver update, is when the driver builds the programs that run on the GPU. Only that time, preparing and starting speech recognition and Qwen3-TTS take longer than usual. From the second start on, the driver uses what it saved.

## Agent jobs don't start

- Check that the CLI of the engine you chose under "Agent" in the settings (codex or claude) is installed and signed in. See [Setting up the Agent](/en/docs/start/agent-cli/).
- claude runs with an API key. Signing in with a Claude.ai subscription doesn't work.
- If Windows says ASIST cannot start a CLI installed with npm, reinstall that CLI with its official installer.
- If Windows says codex's Windows sandbox is not set up, start `codex` once in a terminal and set up the Windows sandbox as it asks. This setup needs administrator rights. See [On Windows](/en/docs/start/agent-cli/#on-windows) for details.

## The calendar or mail won't connect

See "If it does not connect" in [Connecting your calendar](/en/docs/start/calendar/#if-it-does-not-connect) and [Connecting your mail](/en/docs/start/mail/#if-it-does-not-connect).

## At startup, ASIST says it can't read a file

A file such as the settings was written by a newer version of ASIST than the one you are running, or it is damaged. ASIST leaves the file at the location shown untouched. Replace ASIST with the newer version, repair the damaged file, or move it somewhere else, then open ASIST again. For details, see [Where your data is kept](/en/docs/privacy/#settings-file-versions).

## Reporting a bug

Open the log folder from "App log" in "About" in the settings, and write to [GitHub Issues](https://github.com/nyosegawa/asist/issues) with that day's file attached. The log folder is `~/Library/Logs/asist/` on a Mac and `%APPDATA%\asist\logs\` on Windows. Keys and passwords in the log are masked. Report security vulnerabilities with the steps in [SECURITY.md](https://github.com/nyosegawa/asist/blob/main/SECURITY.md), not in a public issue.
